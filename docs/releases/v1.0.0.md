# v1.0.0 — Bilingual Semantic Search with Qwen3-Embedding-4B + Qdrant
> 🌐 Language / Ngôn ngữ: **English** | [Tiếng Việt](v1.0.0.vi.md)

## Summary

`v1.0.0` is the first public release of `nodejs-qdrant-bilingual-search`: an English/Vietnamese open-geography semantic-search API built with Node.js, Hono, Qdrant and Qwen3-Embedding-4B.

The accepted portable profile runs the embedding model with **Transformers / PyTorch / CPU / FP16** while exposing normalized **Float32[2560]** vectors over `binary-f32` transport. The canonical Qdrant snapshot contains 20,000 verified entities.

> **Post-publication documentation note.** This file lives on the moving `main` branch and was updated after the `v1.0.0` publication freeze so that the documentation matches the final public release record. The immutable release identity remains the annotated `v1.0.0` tag; this documentation update does not retarget the tag or alter any controlled release asset.

## Release highlights

- English/Vietnamese semantic retrieval over a canonical 20K open-geography corpus.
- `Qwen/Qwen3-Embedding-4B`, 2560 dimensions, cosine distance.
- Portable Kaggle CPU-FP16 runtime with read-only model loading from `/kaggle/input`.
- Public embedding vectors are normalized `Float32[2560]`.
- Reproducible Node.js CI on Node 22 and Node 24.
- Python embedding-engine tests and real Qdrant integration tests.
- Deterministic dataset, seeding, verification and evidence tooling.
- Repository governance with CODEOWNERS, bilingual contribution/support guidance, security policy, issue/PR templates and dependency-update configuration.
- Separate `runtime/true-fp32` engineering/reference branch.

## Architecture

```text
read-only Qwen3-Embedding-4B model in /kaggle/input
        ↓
Python FastAPI embedding service
        ↓
normalized Float32[2560] / binary-f32
        ↓
Node.js + Hono search API
        ↓
Qdrant canonical 20K collection
```

Default local endpoints:

```text
embedding : 127.0.0.1:8001
Node/Hono : 127.0.0.1:3000
Qdrant    : 127.0.0.1:6333
```

## Known limitations

- Portable CPU demo/runtime, not low-latency GPU serving.
- No reranker.
- No hybrid sparse+dense retrieval.
- No RAG layer.
- No automatic runtime reseeding.
- Relation-style diagnostics can expose ranking limitations even when canonical semantic verification passes.

## Reference work

`runtime/true-fp32` retains the proven prebuilt true-FP32 CPU implementation as an engineering/reference branch. The canonical `v1.0.0` profile remains CPU FP16 because it provides more practical memory headroom on Kaggle.
